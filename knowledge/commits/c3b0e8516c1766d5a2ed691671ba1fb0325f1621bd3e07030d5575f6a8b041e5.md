# c812947 新增 /offday：列出出貨日不是週三或週日的訂單

## Summary
Adds a read-only Discord slash command /offday that scans the master response sheet and reports orders whose shipping date is not a Wednesday or Sunday, plus orders whose date cell is blank or unparseable, grouped by date with the real sheet row numbers. New OffdayOrderAuditor service does the scan (past dates skipped unless all:true), discord_format gains offday_embed/offday_text with attachment overflow, and the handler wires the command onto the organize thread pool. The shipping-day definition (SHIPPING_WEEKDAYS = {2, 6}) is extracted from chat_log_importer into a dependency-free src/utils/shipping_days.py shared by import validation and the auditor. Documentation and a pytest suite are added.

## Why
The form date is a dropdown, but the master sheet can be hand-edited and older rows may already be wrong, so the operator needs an audit tool that can be run any time without touching the spreadsheet. Extracting shipping_days lets the auditor ask "which weekday" without importing the DSPy-heavy importer, and keeps one source of truth for the rule.

## Risks
SHIPPING_WEEKDAYS no longer lives in chat_log_importer, so any other importer of that name would break (a test asserts the importer now uses the shared is_shipping_day). Column positions (orderer 1, receiver 5/6, giftbox 8, family 9, date via SHIPPING_DATE_INDEX) are hard-coded against FORM_COLUMNS. The shipping_days docstring notes existing 2026 responses contain a Tuesday date that contradicts CONTEXT.md, so the rule may need revisiting. The command is read-only and needs no write lock; the `all` option name shadows the builtin inside the handler but is unused there.
