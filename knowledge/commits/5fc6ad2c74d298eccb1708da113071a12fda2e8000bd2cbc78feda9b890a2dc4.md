# 8c45528 Add Jev item judgment with Langfuse tracing and a GPT vs Jev A/B eval

## Summary
Adds TypeSafe Jev as an optional second source for item judgment (category x spec x quantity per recipient): JevItemJudge sends seven closed Choice/Noul questions about the whole chat log in one system_one call and assembles the answers into the same five ItemFields that ChatLogParser yields, with a min-confidence score and a usable floor. The fields-to-form-option mapping is moved unchanged out of ChatLogImporter into a shared item_resolver, and ChatLogImporter gains an ITEM_JUDGE_BACKEND flag (gpt default / shadow / jev) where shadow keeps GPT but logs an item_judge_agreement score and jev uses Jev when confident and falls back to GPT on low confidence or errors. langfuse_tracing gains a generation() context manager so Jev calls are traced with model, usage, cost and per-question answers, and a full A/B harness is added: a 50-item synthetic dataset, schema validation, GPT/Jev task functions, item- and run-level Langfuse evaluators, upload/run scripts and a long design/results doc.

## Why
Item judgment is a closed classification problem that a cheap decision model can answer; the reported A/B on dataset item-judge-v1 showed Jev matching or beating GPT on order accuracy (100% vs 98%) at roughly 25x lower latency and ~20x lower cost, so the commit wires it in behind a flag and keeps a reproducible eval to justify any switch.

## Risks
Default gpt preserves behavior, but shadow mode is not passive: any GPT/Jev disagreement, Jev failure or low confidence appends a problem message to the order, which can push otherwise clean orders into manual review. In shadow/jev modes the entire chat log (customer names, phones, addresses) is sent to a third-party API once per parsed order, adding latency (up to JEV_TIMEOUT_SECONDS each) and a data-sharing concern; the TypeSafe client created per importer is never closed. Jev accuracy is documented as weaker for non-English text, the 50-item dataset is synthetic, and choosing 'more_than_N' maps to N+1 to reuse the resolver's over-limit path. New runtime dependency typesafe-sdk>=0.7.2 (uv.lock updated).
