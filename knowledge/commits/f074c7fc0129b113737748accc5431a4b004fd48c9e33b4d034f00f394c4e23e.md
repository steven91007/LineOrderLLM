# d2501e3 移除已無使用的一次性腳本、學習系統與舊 DSPy 模組

## Summary
Large dead-code cleanup that deletes 30 files: twelve one-off root-level scripts and data files left over from the 2025-08-24 sheet format migration and LIFF/date-parsing debugging, the entire unused "order learning system" (SQLAlchemy models and schema, click CLI, data collector, DSPy learning manager, sample quality evaluator, enhanced DSPy client and its README), the pre-ChatLogParser DSPy modules (ItemParser, MultiOrderParser, SingleOrderParser, OrderTypeClassifier), the Notion progress-logging client, and both requirements files. CLAUDE.md is updated to describe ChatLogParser instead of the removed ItemParser, and SETUP.md switches the install command from pip/requirements.txt to uv sync.

## Why
Per the commit message none of this was imported anywhere: the learning system was an island that could never have run (models.py imports a non-existent `Real` from sqlalchemy, which the diff confirms), the old parser modules were superseded by ChatLogParser, and requirements.txt was stale (flask 3.0, no dspy/langfuse) and out of sync with pyproject.toml. The message also describes trimming pyproject.toml from 22 to 14 dependencies, but pyproject.toml is not part of this diff.

## Risks
Pure removal, so no runtime behaviour changes for the live bot. Anything outside the repo that still ran `pip install -r requirements.txt` or `python -m src.cli.learning_system_cli` will break. The deleted scripts contained hard-coded credential filenames, a spreadsheet ID, a LIFF ID and an ngrok hostname, so removing them also reduces leaked configuration in the tree (they remain in history). The deleted modules referenced other modules (unified_parser, weekday_converter, google_sheets_client, price_calculator, liff_handler, dspy_modules.signatures, order_schemas, dspy_client) whose status is not shown here.
