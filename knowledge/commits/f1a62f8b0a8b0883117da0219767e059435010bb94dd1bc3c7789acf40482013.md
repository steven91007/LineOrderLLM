# 3dad7fe feat: enhance DSPy modules to preserve important information

## Summary
Adds a new DSPy ItemParser module (signature, ChainOfThought predictor, few-shot examples and a regex fallback) that parses free-text item lists into name/quantity JSON while preserving product codes such as 18A/16A. DSPyOrderClient now round-trips the items from single- and multi-order parses back to text and re-parses them with ItemParser. AddressNormalizer's signature and few-shot examples are extended to keep trailing parenthesised notes (e.g. site or company names), its rule fallback now strips and re-attaches such notes, and TaiwanAddressNormalizer drops the complexity gate so the AI path runs for every address. A manual test script and CLAUDE.md notes are added.

## Why
Parsed orders were losing important information: product code prefixes on item names and parenthesised remarks on shipping addresses. The commit adds dedicated handling and prompt examples so both survive LLM normalisation.

## Risks
Every address now goes through the LLM when use_ai is on (removed _is_complex_address check), adding cost and latency. The ItemParser re-parse adds an extra LLM call per order and could rewrite item names that the first parse already had right; failures are silently swallowed. The self.examples lists on both modules are never passed to the predictors, so the few-shot data has no effect at runtime. item_parser.py calls mlflow.dspy.autolog() at import time (project has since moved to Langfuse). The fallback's final return expression is effectively a no-op guard. test_item_address.py is a manual script needing OPENAI_API_KEY, not an automated test.
