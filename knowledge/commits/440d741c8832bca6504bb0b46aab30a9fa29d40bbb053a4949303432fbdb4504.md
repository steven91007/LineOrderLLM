# 655f2e9 全面移除 MLflow，追蹤統一改用 Langfuse

## Summary
Removes MLflow from the whole project in favour of Langfuse: deletes mlflow.dspy.autolog()/set_experiment calls from the four DSPy modules and dspy_client, strips MLflow run/param/metric logging from the learning system (enhanced_dspy_client's enable_mlflow_tracking parameter, order_data_collector's _log_parse_result_to_mlflow, dspy_learning_manager's start_run wrapper), drops the MLflowExperimentLog model and its SQL table/index, and swaps the mlflow dependency for langfuse and openinference-instrumentation-dspy in pyproject/requirements/uv.lock. CLAUDE.md, README_LEARNING_SYSTEM.md and TODOLIST.md are updated so the documented convention no longer asks for MLflow.

## Why
MLflow's DSPy callback was spamming warnings on every parse and tracing had already moved to Langfuse, so running both was pointless. The langfuse/openinference packages were also never declared in pyproject, so a uv sync would have broken tracing.

## Risks
Public API change: EnhancedDSPyOrderClient and OrderDataCollector no longer accept enable_mlflow_tracking/enable_mlflow; callers passing them will fail. Training metrics are still saved to DSPyTrainingLog but no longer to any experiment tracker. Existing databases keep an orphaned mlflow_experiment_logs table that must be dropped manually. uv.lock hunks were omitted from the diff, so exact dependency changes are unknown.
