# f3f2f09 修復 postback 處理中的 result 變數錯誤

## Summary
Fixes an UnboundLocalError in OrderHandler._confirm_all_orders_batch: when no Google Sheets client is configured the fallback branch never assigned 'result', but the success-message code later read it. The fallback branch now initializes result = {'success': True} and the sheet-grouping check uses isinstance(result, dict) instead of hasattr(result, 'get'). A manual test script that runs the postback path with sheets_client set to None and mocked _reply_text is added.

## Why
Confirming orders raised "cannot access local variable 'result' where it is not associated with a value" during postback handling when Google Sheets was not set up (a bug introduced by the merge cb103ed).

## Risks
none identified beyond the test script constructing a real OrderHandler (and therefore a DSPy client) with a dummy API key.

## Files
- `src/handlers/order_handler.py` (M, +2/-1): Initializes result in the no-Sheets branch of _confirm_all_orders_batch and checks isinstance(result, dict) before reading sheet_results. [note](../changes/e14c4340cc44d63f5f6f390316ab5b1c49c142b727af42719ad404fc73546780.md)
- `test_postback_fix.py` (A, +82/-0): New manual script that builds an OrderHandler with mocks, seeds a confirming session, sets sheets_client to None and calls _confirm_all_orders_batch to ensure no NameError occurs.
