# 4175d13 feat: enhance LIFF integration and Google Sheets auto-grouping

## Summary
Large feature commit that adds a LIFF (LINE Front-end Framework) web order editor and automatic per-shipping-date Google Sheets grouping. A new LIFFHandler manages in-memory 2-hour edit sessions, validates edited orders and exposes Flask routes (/liff/edit, /liff/simple, /api/liff/orders/<id>); OrderHandler drops the text-based edit flow in favour of Flex buttons that open the LIFF editor, and a new app_with_liff.py entry point wires it all together with two HTML templates. GoogleSheetsClient gains auto_organize_by_date, routing each order to a YYYYMMDD_星期X worksheet (created on demand with headers) using a new time_utils module that fetches network time and parses ISO, MM-DD and relative Chinese dates. Alongside, shipping_date moves from YYYY-MM-DD to MM-DD across the DSPy parser, schemas and templates, the default DSPy model becomes gpt-4o-mini, MLflow autologging is enabled in dspy_client, config env var names are changed, and several docs and manual test scripts are added.

## Why
Per the message and docs: give users a richer, table-style web editor instead of re-typing orders in chat, and organise the spreadsheet by shipping date with correct weekdays. The accumulated docs and scripts show iteration on a LIFF OAuth login bug where the session ID was lost after redirect, resolved by carrying it in the OAuth2 state parameter and localStorage. The model change and MM-DD date format are stated but not otherwise motivated.

## Risks
Behavioural: text-based order editing is removed, so the old edit_order postback and editing_order status no longer work; all new orders go to per-date sheets instead of the default sheet, and the shipping-date column format changes to YYYY-MM-DD(星期X). config.py now reads GOOGLE_SHEETS_ID / GOOGLE_SHEETS_CREDENTIALS_PATH while app_with_liff.py and LIFF_SETUP.md still use the old names, so deployments can silently lose Sheets config. dspy_client imports mlflow at module load but pyproject.toml does not add it (the project later removed MLflow entirely). time_utils hard-codes BASE_YEAR=2025, calls external time APIs over plain HTTP (with a demo TimezoneDB key) on order writes, and treats network/system times as naive datetimes. get_liff_url is abused in _edit_order_with_liff by passing 'session_id&focus=N' as the session, and a real LIFF ID is hard-coded as the OrderHandler default and in templates/scripts. LIFF sessions are in-memory only (lost on restart), update_liff_session calls write_orders_batch which does not exist on GoogleSheetsClient (only append_multiple_orders), and the simple editor lets any caller save if they know a session ID. organize_existing_orders_by_date copies rows without removing them from the source sheet. Every sheet write lists all worksheets via the API (sheet_cache is never used). Several test scripts and docs embed a concrete ngrok hostname and absolute /home/ubuntu paths and are not pytest-compatible.
