# e107154 Add chat log order import, wired up to Langfuse tracing

## Summary
Adds an end-to-end 'chat log import' feature: a two-stage DSPy module (ChatLogParser) extracts every order from a whole LINE conversation and then re-checks for missed orders; ChatLogImporter validates each order, maps item spec+quantity onto the exact Google Form dropdown strings from the new form_options module, normalizes addresses, de-duplicates against existing sheet rows and appends to the 12-column form-response sheet via a new FormSheetClient. It ships both a CLI (import_chat_log.py, preview by default, --write to commit) and a local Flask GUI (chat_import_gui.py + templates/chat_import.html) for per-order review. It also introduces src/utils/langfuse_tracing.py (Langfuse + OpenInference DSPy instrumentor, one Langfuse session per order, no-op when keys are unset), wires observation spans into the existing dspy_client and openai_client, switches the default DSPy model to gpt-5.6-luna with reasoning-model parameter handling, and adds Cloudflare Tunnel deployment docs and a config template.

## Why
The existing UnifiedOrderParser only handles one message = one order; real LINE chats scatter order data across many messages, mix in chit-chat and amendments, and one orderer may ship to several recipients. The message also explains: single-pass extraction silently drops orders (hence the recall pass); dropdown option strings must be matched exactly rather than generated; the form-response sheet's 12-column layout is incompatible with the older GoogleSheetsClient; Langfuse sessions are trace-level so each order needs its own root trace; gpt-5.x needs max_completion_tokens and temperature 1.0 which DSPy 2.6 does not detect; dspy.settings.configure raises in Flask worker threads so dspy.context is used; and Cloudflare Tunnel replaces ngrok's changing URLs.

## Risks
Default DSPY_MODEL changes for every consumer of config.DSPY_MODEL, not just the new importer. openai_client now imports langfuse.openai as a drop-in wrapper and both legacy clients call init_tracing() at import time. Address normalization can rewrite city names differently from existing sheet data (the code notes a --no-normalize-address escape hatch). SHIPPING_WEEKDAYS is hard-coded to Wed/Sun and flagged as possibly out of date, producing 'review' status rather than blocking. Few-shot examples embed sample personal-looking data inline in the module. The GUI keeps parse results in process memory under a single global, so concurrent users would clobber each other. The Cloudflare doc notes the webhook handler is still synchronous and needs a follow-up.

```text
Add chat log order import, wired up to Langfuse tracing

Parse LINE chat logs into orders and write them to the Google Form responses sheet.
Unlike the existing UnifiedOrderParser, this handles a whole conversation:
order details are spread over many messages, mixed with small talk and changes, and one buyer may ship to several recipients.

Main components:
- ChatLogParser: a two-pass DSPy module. In testing, a single extraction silently missed orders,
  and different models missed different ones, so it re-checks after extracting.
- form_options: maps item/size/quantity to the full form dropdown option strings,
  checked verbatim against the form. Gift boxes use Chinese numerals, family packs use Arabic numerals,
  and the 18A seven- and eight-box prices have no thousands separator in the form; all copied as-is.
- FormSheetClient: the form responses sheet is a single 12-column tab,
  incompatible with GoogleSheetsClient's auto-tabbed 10-column format, so it is a separate class.
- ChatLogImporter: ties together parsing, validation and writing; by default only writes orders with no issues.
- chat_import_gui.py: a local web UI; paste a log, preview and tick each order, then write.

Langfuse tracing is split as "one session per order", with the session id taken from
recipient/phone/delivery date. In Langfuse, session is a trace-level attribute,
so each order must be its own root trace — as child spans under one trace,
only the last order's session would survive and earlier ones would be overwritten.

Other:
- Default model changed to gpt-5.6-luna. It is a reasoning model: it doesn't take max_tokens,
  temperature must be 1.0, and DSPy 2.6's detection only recognizes names starting with o1/o3/o4.
- langfuse_tracing provides both setup/trace and init_tracing/observation
  naming, so existing calls in dspy_client and openai_client keep working.
- Use dspy.context instead of dspy.settings.configure(),
  which otherwise raises when Flask handles requests on worker threads.
- Add Cloudflare Tunnel deployment docs, replacing ngrok whose URL keeps changing.
```
