# 8b27bd3 Fix two issues that fail a whole import and hide the error

## Summary
Fixes two bugs that could make a whole chat-log import fail with the real error hidden. ChatLogParser._extract_orders' fallback replaced a greedy r'\[.*\]' regex with json.JSONDecoder().raw_decode starting at the first '[' or '{', so trailing prose or a second array after the JSON no longer breaks parsing. langfuse_tracing.trace() no longer wraps the yield in try/except; it uses an ExitStack so only span-creation failures are swallowed while exceptions from the caller's body propagate unchanged.

## Why
The greedy regex swallowed everything up to the last ']' whenever the model added a bracketed remark, losing every order in the batch. The tracing context manager caught body exceptions and yielded again, which Python turns into 'generator didn't stop after throw()', masking the original traceback and making the first bug hard to diagnose.

## Risks
Exceptions inside traced blocks now surface to callers, which is intended but changes behaviour for any code that relied on them being swallowed. raw_decode takes only the first JSON value, so a model output with multiple arrays keeps just the first.

## Files
- `src/utils/dspy_modules/chat_log_parser.py` (M, +13/-4): Fallback JSON extraction now uses raw_decode from the first '[' or '{' and raises a ValueError chaining the decode error instead of a greedy regex. [note](../changes/dee29bbc5b5d2f93096d1105531b1ef0b7be89d54243ed919790a11f25040887.md)
- `src/utils/langfuse_tracing.py` (M, +26/-12): trace() builds the span and session propagation inside an ExitStack; only setup errors fall back to _NullSpan, and body exceptions propagate through the stack. [note](../changes/7a897383e2c5935edb09484560860c3e1a33220e78023c5d805f616874a61799.md)

Fix two issues that fail a whole import and hide the error

1. _extract_orders' fallback used a greedy \[.*\] match that ran from the first [ to the
   last ] in the output. If the model added one more sentence containing ] after the JSON, the whole thing
   failed to parse and every order in that import vanished. Now use raw_decode to take the first complete JSON value
   starting at the first [ or {, ignoring anything after it.

2. langfuse_tracing.trace() wrapped the whole with (including the yield) in try/except,
   so as soon as the caller's body raised, it was caught and then yielded again — contextmanager
   doesn't allow yielding after a throw, so Python turned it into
   RuntimeError: generator didn't stop after throw(),
   and the original error and traceback were lost.

   Issue 1 was hard to track down precisely because issue 2 hid it: all you could see was that RuntimeError,
   with no clue which line actually failed.

   Now only a failure to create the span may be swallowed; errors after the yield propagate unchanged,
   and ExitStack still closes the span properly.

Both verified: JSON parsing covers a plain array, code fences, surrounding text, two arrays,
a single object, an empty array and pure garbage input; tracing was confirmed to propagate exceptions unchanged
with Langfuse actually enabled.
