# 086c449 feat: fix Google Sheets API connection and range parsing issues

## Summary
Stops hardcoding the 'Sheet1' tab name in GoogleSheetsClient: a new _get_sheet_title helper reads the spreadsheet metadata and returns the first sheet's title (falling back to 'Sheet1'), and append_order, append_multiple_orders, get_recent_orders and test_connection build their A1 ranges from it, while create_sheet_if_not_exists inlines the same lookup. Adds test_google_sheets_api.py, a unittest suite with 11 tests (environment, init, validate_setup, connection, header creation, single and batch append, recent orders, error handling, item formatting) driven by env vars and a small CLI with --validation-only.

## Why
Range parsing failed when the target spreadsheet's first tab was not named 'Sheet1'; deriving the title dynamically fixes those API errors. The test suite verifies the client end to end (message reports 11/11 passing).

## Risks
Every write/read now performs an extra spreadsheets().get call to look up the title. Only the first tab is ever used. The tests write real rows into the configured spreadsheet and offer no cleanup (--cleanup only prints a note; --quick is parsed but unused). Message items about removing sample code and fixing type checks are not evident from the diff since the test file is new.
