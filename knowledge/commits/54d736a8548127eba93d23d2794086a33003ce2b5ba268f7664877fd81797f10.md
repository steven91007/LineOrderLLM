# f5eadf0 修復星期幾日期轉換邏輯

## Summary
Makes weekday-based shipping dates come from the raw order text instead of the LLM output: a new UnifiedOrderParser._extract_date_from_text searches the cleaned text with regexes for labels such as 預計出貨日/出貨日/發貨日期/送貨日期 followed by a weekday token (and a bare weekday token as last resort), converts it with WeekdayConverter, and in forward() the result overrides shipping_date on every cleaned order whenever it is found. Adds a manual test script that compares the parsed date against WeekdayConverter.get_next_weekday_date('星期天').

## Why
The DSPy model was returning wrong dates for weekday inputs (the message cites '星期天' on 8/15 yielding 10-08 instead of 08-17), so the author stopped trusting the model's date and re-derived it from the text.

## Risks
The extracted date is applied to all orders in a multi-order message, so orders with different weekdays get the same date, and it overrides any explicit numeric date the model extracted if a weekday word appears anywhere. The generic fallback pattern matches the first weekday token in the text, so form labels like '預計出貨日(星期日/星期三)：星期三' resolve to the label's first option rather than the user's answer (the labelled patterns do not match when a parenthesis follows the label). The character class [星期週禮拜]+ also matches odd strings; and the regression noted in 64605a6 for YYYY-MM-DD input remains.
