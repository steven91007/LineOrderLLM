# 84bd69a Merge feature/liff-integration-v2 into master

## Summary
Merge of feature/liff-integration-v2 into master. It brings in a LIFF (LINE Front-end Framework) web order editor: a new LIFFHandler with in-memory 2-hour editing sessions, Flask routes (/liff/edit, /liff/simple, GET/PUT /api/liff/orders/<session_id>, /api/liff/cleanup), two Tailwind HTML templates, and a new app_with_liff.py entry point; OrderHandler's Flex carousel now offers '網頁編輯' / '編輯此訂單' buttons that open the LIFF editor, and the old text-based edit flow (editing_order status, _process_order_edit) is removed. It also adds a TimeUtils helper (network time lookup with 5-minute cache, date parsing, Chinese weekday formatting) and makes GoogleSheetsClient automatically create and write to per-shipping-date worksheets named YYYYMMDD_星期X, with batch writes grouped by sheet and a helper to reorganize existing rows. The DSPy parser and JSON schemas switch shipping_date from YYYY-MM-DD to MM-DD (with a regex-based _clean_date), DSPyOrderClient's default model becomes gpt-4o-mini and MLflow autologging is enabled, config.py switches to GOOGLE_SHEETS_ID / GOOGLE_SHEETS_CREDENTIALS_PATH env vars, and several docs and ad-hoc test scripts are added.

## Why
Users needed a richer way to fix parsed orders than re-typing the whole order in chat, so a web editor inside LINE was built; several iterations on the LIFF OAuth redirect (documented in the flow diagram and test scripts) ended with carrying the session ID via the OAuth state parameter and a clean redirect URI. Separately, the shop wanted orders grouped by shipping date in Google Sheets, which motivated the time utilities and per-date worksheets.

## Risks
The Flask /liff/edit route returns HTTP 400 when the 'session' query parameter is missing, but the new get_liff_url intentionally emits a clean liffRedirectUri (…/liff/edit) with the session only in a 'sessionId' parameter of the LIFF URL, so the redirect target itself may be rejected. config.py now reads GOOGLE_SHEETS_ID / GOOGLE_SHEETS_CREDENTIALS_PATH, while app_with_liff.py and LIFF_SETUP.md still use GOOGLE_SHEET_ID / GOOGLE_CREDENTIALS_PATH. dspy_client.py imports and configures mlflow but mlflow is not added to pyproject.toml (only requests is). OrderHandler._confirm_all_orders_batch references a 'result' variable that is unbound when no Sheets client is configured (fixed in the following commit f3f2f09). TimeUtils hard-codes BASE_YEAR = 2025 and calls plain-HTTP public time APIs (5 s timeout) from get_current_time, which is invoked on every parse/append, so Sheets writes gain network latency and behaviour will drift after 2025. GoogleSheetsClient makes a spreadsheets().get call per sheet lookup (the sheet_cache attribute is never used) and organize_existing_orders_by_date copies rows without removing them from the source sheet. The MM-DD shipping_date change drops the year everywhere, including the JSON schemas, which is a breaking format change for any consumer expecting YYYY-MM-DD. A default LIFF app ID is hard-coded in OrderHandler, and a development ngrok hostname is hard-coded in docs and test scripts. LIFF sessions live only in process memory and are lost on restart; the batch success message is built from sheet names. Text-based order editing is removed, so without a LIFF ID users can no longer edit an order before confirming.
