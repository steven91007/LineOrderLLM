# 217aea7 feat: 增強訂單處理系統與 Google Sheets 功能

## Summary
Adds an order-editing flow to the LINE handler: each carousel bubble's button changes from 'confirm this order' to 'edit this order', which puts the session into an 'editing_order' state, shows the current values and asks the user to re-enter the order; the reply is re-parsed with DSPyOrderClient and replaces that order in the session before the carousel is shown again. Batch confirmation now calls sheets_client.append_multiple_orders once instead of appending orders one by one. GoogleSheetsClient gains test_connection (reads spreadsheet metadata and one cell) and validate_setup (credentials file, service init, connection and header checks with recommendations).

## Why
Users needed a way to fix an individual mis-parsed order before submitting, and the commit prefers a single batch write for efficiency; the new diagnostic methods make Google Sheets configuration problems easier to spot.

## Risks
Per-order confirmation is gone; the only submit path is the batch button. When editing, only the first parsed order is used and it overwrites the original in place. Batch failure reporting is all-or-nothing (every order is listed as failed if the single call fails). test_connection hardcodes the 'Sheet1' range (fixed in the next commit) and assumes write access whenever a read succeeds. validate_setup calls create_sheet_if_not_exists, so a 'validation' can write a header row.
