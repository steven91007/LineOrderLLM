# 90d32a1 feat: 多訂單處理與寄件人選填功能增強

## Summary
Extends parsing to handle up to five orders in one message and makes sender name/phone optional. OpenAIClient gets a new multi-order system prompt returning order_type 'single'/'multiple'/'error', a format pre-check that returns a 'single_order' suggestion on failure, and validation split into single/multiple helpers with sender no longer required. OrderHandler gains an overview of detected orders, per-index browsing with prev/next buttons, confirm-one/confirm-all postbacks, a parsing-failure template suggesting single entry, and shared summary/save helpers; GoogleSheetsClient writes '未提供' for missing optional fields, returns the order_id and adds an append_multiple_orders batch method. SETUP.md is rewritten as v2.0 and pyproject.toml gains google/openai dependencies.

## Why
Users send several orders in one message and often omit sender details; the commit message frames this as multi-order support, optional sender, one-by-one confirmation and friendlier failure handling.

## Risks
_show_parsing_failure_with_suggestion is defined with only an event parameter but _process_order_text calls it with (event, error_message), so the OpenAI-failure path that carries a 'single_order' suggestion raises TypeError instead of showing the template. append_multiple_orders is added but the handler still saves orders one at a time via _save_order_to_sheets_silent. After confirming order N the user must tap 'next' from an earlier template to reach N+1; the reply only reports the remaining count. Confirm-all reports partial failures but cannot say which orders failed. The literal '\n' escapes from the previous commit are fixed as a side effect. The 'retry_single_order' action resets status to waiting_order_text only if a session still exists, but sessions are deleted after a failed parse, so that button silently does nothing useful.
