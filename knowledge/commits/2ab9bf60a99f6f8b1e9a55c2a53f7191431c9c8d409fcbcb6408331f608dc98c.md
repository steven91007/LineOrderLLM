# 8b39654 修復訂單解析對 * 數量格式的支援

## Summary
Adds support for the '*N' quantity notation (e.g. '18A禮盒 *4') in order parsing: a new regex pattern r'\*\s*(\d+)' is prepended to the quantity patterns in both UnifiedOrderParser and ItemParser, new few-shot examples using '*' quantities are added, and the prompt rules mention '*2'. Phone validation in UnifiedOrderParser._clean_phone is loosened from a minimum of 8 characters to 7. A manual test script test_order_parsing_fix.py is added, and 'dotenv>=0.9.9' is added to pyproject.toml (uv.lock updated).

## Why
A real order using the shop's form template wrote the quantity as '18A禮盒 *4' and was not parsed correctly; the same order also had a shorter phone number than the previous 8-character minimum allowed.

## Risks
The lowered phone-length threshold accepts more malformed numbers. The new few-shot examples embed what appear to be real customer details from the failing order. 'dotenv' was added to dependencies although the code imports python-dotenv; the PyPI 'dotenv' package is a different distribution (it may pull python-dotenv transitively, but it is likely not what was intended). uv.lock changes were omitted from the diff.
