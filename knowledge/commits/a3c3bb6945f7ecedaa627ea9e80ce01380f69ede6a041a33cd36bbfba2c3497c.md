# c50dd2b 鎖定已出貨的日期分頁，並加上兩種出貨日過期的警告

## Summary
Three related changes around shipping dates in the past. (1) SheetDateOrganizer.organize() now treats date tabs earlier than today as locked: they are not rebuilt, are excluded from the stale-tab purge, and get a warningOnly protected range added via the Sheets API (skipped if a protection already exists, failures only logged); the result gains locked_sheets and the Discord preview/result embeds show a lock marker and count. (2) ChatLogImporter now passes the reference datetime into _resolve_shipping_date and appends a "date already passed" review problem when the parsed date is before today, without blocking the write. (3) /offday gains a third "backdated" category for rows whose shipping date is earlier than the form timestamp; it ignores the include_past filter and can overlap with the offday category. Docs and tests are updated, including a new tests/test_sheet_locking.py.

## Why
A shipping date in the past either means a historical record that must not change (so the day-of shipping list should not be rewritten when someone later edits the master sheet) or a data-entry/LLM error such as a relative date like "last Wednesday" resolved to the wrong year, which should be surfaced. warningOnly protection was chosen so the service account cannot lock itself out.

## Risks
Bug: organize() calls `_is_past_sheet(...)` but the function is defined and exported as `is_past_sheet`, so any organize run with at least one date group raises NameError; the tests only exercise is_past_sheet and the formatters directly, so they did not catch it (fixed later in commit 1e454fe). Behaviour change: past date tabs are never rebuilt, so late corrections to old orders no longer propagate to them; a past-dated group whose tab does not exist yet will be created empty and protected. The importer now flags every backfilled past order as needing review. _get_existing_sheets requests protectedRanges, so sheet metadata shape changes. New backdated tests are appended after the `if __name__ == "__main__"` block in test_offday_orders.py, which still works under pytest but is untidy.

   補登舊訂單時還是進得去。

   填表當下出貨日就已經是過去的日期，一定是填錯。這類刻意不受 all 參數影響：
