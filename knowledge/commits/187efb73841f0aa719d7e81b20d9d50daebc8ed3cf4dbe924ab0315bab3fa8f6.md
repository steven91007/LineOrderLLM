# 532f619 Merge pull request #6 from steven91007/feature/google-sheets-api-fixes

## Summary
Merge of PR #6 (feature/google-sheets-api-fixes) into master. It introduces a DSPy-based order parsing stack (DSPyOrderClient, UnifiedOrderParser plus single/multi parsers, classifier, signatures, JSON schemas and validators) selectable through ORDER_CLIENT_TYPE alongside the existing OpenAIClient, a hybrid rules+LLM Taiwan address normalizer applied by both clients, and an ItemParser that preserves product codes. The LINE OrderHandler is rewritten to show a Flex Message carousel with per-order edit and confirm-all actions and to batch-write orders. GoogleSheetsClient stops hard-coding 'Sheet1' and gains test_connection/validate_setup, with an example script, a unittest suite and guides; a NotionClient, CLAUDE.md, TODOLIST.md and MLflow/dspy/jsonschema dependencies are also added.

## Why
The branch name and guide point at fixing Google Sheets API usage (the sheet tab name was hard-coded and there was no setup diagnostics), while the bulk of the merged work moves order parsing to DSPy for stricter JSON output and validation, adds address normalization so sheet rows have consistent Taiwan addresses, keeps product codes like 18A in item names, and gives users an edit-before-confirm flow in LINE. CLAUDE.md records DSPy plus MLflow autolog as the project-wide AI convention.

## Risks
OrderHandler accepts dspy_api_key/dspy_model/dspy_max_retries but constructs DSPyOrderClient with only openai_api_key, so DSPY_MODEL and DSPY_MAX_RETRIES are ignored and the client key falls back to OPENAI_API_KEY. The DSPy client returns {'orders', 'total_orders'} without order_type, while the legacy OpenAI path still returns order_type single/multiple; test_dspy.py checks order_type == 'multiple' and would misreport. FlexMessage/FlexContainer are used in order_handler without an import visible in the diff. Module-level side effects: address_normalizer, item_parser and unified_parser instantiate DSPy modules and call mlflow.dspy.autolog()/set_experiment at import, and taiwan_address imports address_normalizer, so importing OpenAIClient now pulls in dspy and mlflow; TaiwanAddressNormalizer defaults to use_ai=True so every address triggers an LLM call (before any LM is configured in the OpenAI path). OpenAIClient defines _normalize_addresses_in_result twice. Env var names differ between config.py (GOOGLE_SHEET_ID, GOOGLE_CREDENTIALS_PATH) and the guide/example/tests (GOOGLE_SHEETS_ID, GOOGLE_SHEETS_CREDENTIALS_PATH). .gitignore now ignores every *.json file. validate_setup uses os.path.exists and test_connection catches HttpError without imports shown in the diff. _get_sheet_title does an extra spreadsheets().get per write. The few-shot examples in unified_parser embed what appear to be real customer names, phones and an address. Removal of per-order confirmation postbacks (confirm_single_order etc.) breaks any in-flight sessions from the previous UI.
