# e0ee298 Deploy with fetch + reset --hard so old clones on the VM can follow the rewritten master

## Summary
Changes the GCE deploy step in .github/workflows/deploy.yml from `git pull` to `git fetch origin master` followed by `git reset --hard origin/master`, with a comment explaining that master's history was rewritten to purge a private key.

## Why
After a force-pushed history rewrite the VM's existing clone diverges from origin/master, so `git pull` would fail or create a merge; fetch + reset makes the deploy converge on whatever master now is.

## Risks
`reset --hard` discards any local edits on the VM checkout, which is the intended behaviour for a deploy target but would silently drop manual hotfixes made there.
