# 038286e 新增 Discord 訂單機器人

## Summary
Adds a Discord bot (discord_bot.py entry point plus src/handlers/discord_handler.py, discord_views.py and discord_format.py) that lets an authorised user DM the bot a LINE chat log (pasted text or a .txt attachment), parses it with the existing ChatLogImporter on a dedicated single-worker thread pool, posts an embed preview with per-order details, and only writes to the Google Sheet after a button confirmation; a /organize slash command previews and then runs SheetDateOrganizer to rebuild the per-shipping-date tabs. New DISCORD_* settings are added to config.py and .env.example, the .env.example Google Sheets variable names are corrected to the ones config.py actually reads (GOOGLE_SHEETS_ID / GOOGLE_SHEETS_CREDENTIALS_PATH), Langfuse keys are documented, and DISCORD_SETUP.md plus a pure-function unit test suite for the formatting layer are added. No underlying service code is changed.

## Why
The commit message explains it wants the same functionality as chat_import_gui.py and organize_by_date.py but usable from a phone; those tools are kept. Key design choices are documented inline: imports go through on_message rather than a slash command because parsing can exceed the 15-minute interaction token; DMs are always allowed so the privileged message-content intent is only requested when a server channel is configured; each blocking service runs on its own max_workers=1 executor because the googleapiclient service object is not thread-safe; only one pending preview per channel is kept because parse() snapshots the sheet's duplicate keys once, so two concurrent previews could both be confirmed and double-write; previews stay in memory only because they contain customer personal data; DISCORD_AUTHORIZED_USERS is separate from LINE's AUTHORIZED_USERS and an empty list refuses startup rather than failing open. The .env.example rename fixes variable names that never matched config.py.

## Risks
Introduces a new runtime dependency on discord.py that is not added to any dependency manifest in this commit. The .env.example fix means anyone who copied the old GOOGLE_SHEET_ID / GOOGLE_CREDENTIALS_PATH names must rename them. Parsing cannot be cancelled once started (asyncio.wait_for is deliberately avoided), so a hung LLM call blocks all further imports until restart, and pending previews are lost on restart. _check_config reads config.GOOGLE_SHEET_ID / GOOGLE_CREDENTIALS_PATH, which must already exist in config.py. The 10-minute eviction loop only drops pending state 1.5x past the confirm timeout. One test assertion (test_organize_preview_falls_back_to_attachment) is effectively always true. The handler stores private-looking attributes on the bot object (bot._order_handler) and organize_command reaches into handler._organize_lock.

新增 Discord 訂單機器人

私訊機器人貼上聊天紀錄或丟 .txt，解析成訂單後顯示預覽，按按鈕才寫入
試算表；另有 /organize 把總表依出貨日拆成日期分頁。等同 chat_import_gui.py
和 organize_by_date.py 的功能，差別是可以從手機操作，那兩個工具都保留。

底層服務沒有任何改動，直接沿用 ChatLogImporter 和 SheetDateOrganizer。

幾個關鍵決定：

- 匯入走 on_message 而不是斜線指令。解析要花好幾分鐘，斜線指令的
  interaction token 只有 15 分鐘，訊息路徑則沒有期限。
- 私訊一律放行，DISCORD_ORDER_CHANNEL_ID 是選填。私訊不受 message content
  這個特權 intent 限制，所以純私訊用法連 Developer Portal 都不用設定，
  程式也只在真的要讀頻道文字時才要求那個 intent。
- 服務呼叫全部丟到各自 max_workers=1 的執行緒池，不用 asyncio.to_thread。
  googleapiclient 的 service 不是 thread-safe，共用 executor 會讓它落在
  不同執行緒上。
- 同一個頻道只留一批待確認的預覽。parse() 會抓一次試算表的重複鍵快照，
  兩批預覽並存時後解析的那批看不到前一批，兩邊都確認就會重複寫入。
- 預覽只放記憶體，不落地：裡面有收件人姓名、電話、地址和匯款末五碼。

DISCORD_AUTHORIZED_USERS 和 LINE 的 AUTHORIZED_USERS 刻意分開，兩邊是
不同的 ID 空間。留空會拒絕啟動，不會 fail-open。

順手修掉 .env.example 裡的 GOOGLE_SHEET_ID / GOOGLE_CREDENTIALS_PATH，
它們和 config.py 實際讀的 GOOGLE_SHEETS_ID / GOOGLE_SHEETS_CREDENTIALS_PATH
從來沒對上過。
