# 0eb5d8a 新增訂單匯總與學習系統，並停止追蹤 .env

## Summary
Large combined commit that (1) adds a '#匯總' LINE command backed by a new OrderSummaryGenerator and GoogleSheetsClient.get_orders_by_date, (2) reshapes the Google Sheets row layout to a 10-column business format with totals computed by a new PriceCalculator (tiered gift-box pricing), (3) fixes DSPy date handling by passing the current date into UnifiedOrderParser, generating a weekday conversion table, adding absolute-date parsing and no longer letting regex extraction override DSPy's date, and (4) drops in an unwired DSPy 'learning system' (SQLAlchemy models, schema.sql, data collector, learning manager, quality evaluator, enhanced client, click CLI, README, extra requirements). It also adds CONTEXT.md and docs/agents/* agent guidance, several one-off sheet migration/conversion scripts and text backups for the 2025-08-24 worksheet, three verify_*.py scripts, and deletes fifteen root-level ad-hoc test scripts. .gitignore now excludes *.xlsx/*.xls/*.csv.

## Why
The commit message says the goals were to stop tracking .env and customer spreadsheets (personal data), document the domain vocabulary and agent workflow, add order summarisation and tiered pricing for the boss's daily report, land the learning system for future use, replace throwaway tests with verify scripts, and fix weekday/date conversion, order parsing and sheet tab logic. The diff supports this: SUMMARY_FIX_NOTE.md documents an 'Invalid reply token' bug in the summary reply, and the parser changes address DSPy weekday dates being overwritten by a regex that used the wrong reference date. No .env change appears in the provided file list, so the untracking cannot be confirmed from the diff.

## Risks
Sheet layout change is breaking: new rows have 10 columns without a shipping-date column, so _get_orders_from_sheet no longer filters by date (explicit TODO) and treats any row with an address as a match; when no date-named tab exists it aggregates every worksheet, so '#匯總' can report wrong totals. _ensure_headers still writes an 11-column header including 寄件地址 while append writes 10 columns and readers map column B to sender_address, so columns are misaligned depending on which path created the tab. Existing tabs in the old 11-column layout are read incorrectly. The organizer still reads shipping date from column index 7, which is now the address. The learning system imports mlflow/sqlalchemy/sklearn/psutil (not in main requirements), creates a SQLite DB and tables at import time, stores raw order text and confirmed-order personal data locally, and its 'training' only swaps few-shot examples and scores by order-count match; it is not wired into handlers. One-off scripts hard-code a service-account filename and spreadsheet ID and overwrite live worksheets; backup/converted text files commit order-like personal-data rows. verify_*.py and final_summary.py are print-based scripts rather than assertions. Deleting the root test scripts removes the only coverage for LIFF/OAuth/postback flows.
