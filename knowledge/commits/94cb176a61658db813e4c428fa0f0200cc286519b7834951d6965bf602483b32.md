# cee488d feat: 升級地址標準化為混合式 AI + 規則處理

## Summary
Turns address normalisation into a hybrid pipeline. A new DSPy module AddressNormalizer (ChainOfThought over AddressNormalizerSignature, with a list of few-shot examples and a small built-in district fallback) is instantiated as a module-level singleton and calls mlflow.dspy.autolog() at import. TaiwanAddressNormalizer gains a use_ai flag: for addresses judged 'complex' (old county names, district-only, contains 台/臺, numbered prefixes, or shorter than 8 chars) it calls the DSPy module and then applies rule post-processing, falling back to pure rules on any exception. Adds CLAUDE.md recording the DSPy-everywhere and MLflow-autolog decisions, rewrites the address test script to compare AI vs rules modes, and adds test_ai_address.py which configures dspy.LM with gpt-4o-mini.

## Why
Rule tables cannot cover every messy address form; the message argues an LLM should handle complex cases with rules as pre/post-processing and fallback, tracked via MLflow.

## Risks
_is_complex_address treats any address containing '台' or '臺' as complex, so nearly every Taiwanese address now triggers an LLM call; when no DSPy LM is configured in-process (e.g. the OpenAI client path) each call raises and silently falls back, adding latency and hiding errors. Importing taiwan_address now imports dspy and mlflow and runs mlflow.dspy.autolog() as an import side effect, and the AddressNormalizer singleton is built at import time. The few-shot examples are constructed but never used by the module. The AI branch skips the rule pipeline's county/district upgrade tables (post-processing only fixes 台->臺 and whitespace), so results depend on the model. The default use_ai=True changes behaviour for all existing callers. The MLflow instruction recorded in CLAUDE.md was later superseded by Langfuse per the current CLAUDE.md. The AI test script requires a live API key.
