# 1ce28ab Add form options and order parsing support for the 雙雙對對 item

## Summary
Extends full pipeline support for the 雙雙對對 item beyond the price calculator. form_options gains a SHUANGSHUANG_OPTIONS table (1-4 sets, proposed option strings not yet verified against the Google Form), MAX_SHUANGSHUANG_SETS, shuangshuang_option() and an updated describe_options(). ChatLogOrderSignature gets a new shuangshuang_sets output field, a rule not to treat the item as a family-pack spec, and a new few-shot example; ChatLogImporter maps the count to an option string written into the family-pack column (flagging conflicts when both family and 雙雙對對 appear, and warning that the option string is unverified); shipping_summary parses the new option format as its own category with no spec.

## Why
Only the price table knew the item, so manually entered rows like '雙雙對對*4' were flagged as unrecognized by the shipping summary and the LLM parser could not extract it (commit message).

## Risks
The option strings are a proposal and the form column has not actually been extended, so imports of this item always carry a 'please verify' problem note. Writing the item into the family-pack column means an order with both family packs and 雙雙對對 cannot be represented and is flagged for manual handling. _parse_option's return tuple grew from 3 to 4 elements, so any other caller would break. The new few-shot example includes a synthetic person name, phone number and address. The '雙雙對對*N' shorthand from the message is still not matched here; that follows in 83b3249.

Add form options and order parsing support for the 雙雙對對 item

Previously 雙雙對對 (Shuangshuang Duidui bundle) was only added to the price_calculator price list; form_options, ChatLogParser
and shipping_summary didn't know the item, so a manually entered 「雙雙對對*4」 was flagged
as unrecognized by the shipping summary. This fills in the whole path: form option strings (written to the
family-pack column, 1-4 sets), the LLM extraction field shuangshuang_sets, column mapping and conflict
checks on import, and a separate category parser in the shipping summary.

The form option strings are a proposed format; they haven't been added to the Google Form yet
or checked verbatim. A note to that effect is left in form_options.py.
