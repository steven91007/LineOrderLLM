# 37f7e2f feat: unify order processing flow and Flex Message carousel

## Summary
Replaces the classifier + single/multi parser pipeline with a new UnifiedOrderParser DSPy module that always returns a JSON array of orders; DSPyOrderClient.parse_order now returns {'orders': [...], 'total_orders': N}, validates each order itself (required fields, phone regex, items, max 5 orders) and normalises addresses per order, while the old order-type heuristics, legacy validators and the ItemParser round-trip are deleted. OrderHandler drops the single/multiple confirmation branches in favour of one Flex Message carousel with a bubble per order plus a final 'confirm all' bubble, adds _confirm_all_orders_batch that generates ORD-YYYYMMDD-XXXXXXXX ids and appends every order to Google Sheets, and removes the old ButtonsTemplate-based confirm/navigate methods. MLflow experiment 'line_order_experiment' is set at import time.

## Why
The message states the goal: treat every input uniformly as an array of orders, remove the fragile single-vs-multiple classification, and give users a swipeable carousel with a one-tap batch submit instead of template buttons.

## Risks
Breaking API change: parse_order's result shape and the 'suggestion' key are gone, and postback actions were renamed, so any client or session mid-flow using the old actions breaks. UnifiedOrderParser._clean_date only accepts YYYY-MM-DD, so dates like '9/11' are dropped to null; receiver_name defaults to a placeholder string when missing, which passes validation. The few-shot examples list is never attached to the predictor, and one example embeds what appear to be real customer names, phone numbers and an address in source. The handler uses FlexMessage, FlexContainer, datetime and uuid but the diff shows no import changes, so import correctness is not evident. mlflow.set_experiment runs at import in two modules.
